# 主界面剧情与签到奖励

玩家信息框右侧提供两个入口：彩色旗帜「剧情奖励」、彩色日历「签到奖励」。图标后方的放射光缓慢旋转，有可领取奖励时显示呼吸提示点。

两种奖励共用屏幕中央的横向金属纹理栏目，方形节点由横向金线连接。节点上方显示奖励数量或卡牌稀有度、名称，下方显示领取按钮。支持鼠标拖动、触摸横向滑动、滚轮、左右按钮，以及列表聚焦后的左右方向键。点击外部空白或 Esc 关闭。

## 剧情奖励

按 **1-1 → 4-4** 排列 16 个关卡节点，依次循环金币、水晶、卡牌。每关第一次通关后，该关节点可领取一次。通关点亮节点边缘，相邻两个通关节点之间的连线也点亮；领取后显示勾记。

当前前三章共 12 个关卡正常接入已有通关记录。第四章的 4 个节点展示后续奖励，保持未开放；没有添加关卡或敌方牌组。将来对应 `4-1` 至 `4-4` 通关记录出现后，自然满足领取条件。

这是额外的剧情里程碑奖励，原有战斗结算的金币、经验和掉落保持原规则。重打已通关关卡不会重复获得此处的节点奖励；更新前已有通关记录的玩家可以补领。

## 签到奖励

- 共 30 个累计签到节点，首日点击「签到领取」获得第 1 日奖励。每个本地日历日最多领取一个节点。
- 漏签不清零，不扣已有奖励；下一次签到继续累计。当天不能提前领取后续节点，也不能补领漏掉的自然日期。
- 依次循环金币、水晶、卡牌。第 1 / 4 / 7 … / 28 日金币依次为 100 / 130 / 160 … / 370；第 2 / 5 / 8 … / 29 日水晶依次为 10 / 13 / 16 … / 37。
- 第 3 / 6 / 9 / 12 / 15 / 18 / 21 / 24 / 27 / 30 日分别领取 C / C / C+ / C+ / B / B / B+ / B+ / A / A 卡牌一张，增长慢于剧情奖励。
- 已签到节点的边缘和连线发亮。30 日领取完毕后显示完成，不自动重置开启下一轮。
- 日期使用玩家存档的本地时钟，与每日商店一致；开发日期覆盖 `?day=YYYYMMDD` 同样生效。日期回退至最后一次签到日期或更早时不能再次领取。

卡牌奖励只从对应稀有度的完整普通卡牌中选取，按节点稳定确定；预览的卡牌就是实际获得的卡，重新打开、刷新或重新登录不会重抽。卡面可悬停查看全局介绍框，获得重复卡正常增加牌库数量。

## 存档与维护

`ProfileState.campaign.clearedStages` 继续记录通关关卡；新增 `ProfileState.rewards`：

```ts
{
  claimedStoryIds: ['1-1'],
  checkIn: [{ day: 1, dayKey: '20261010' }]
}
```

签到日序与实际日期同记录，因此没有重复维护一个容易漂移的「累计天数」。领取记录和金币 / 水晶 / 库存变化在同一次经济事务中写入，保存成功后才点亮签到节点和标记领取；保存失败不发放奖励、不推进签到。领取过程中禁用按钮，事务层再次检查通关、日期和领取记录。

存档格式升级为 v2，v1 自动补充空奖励账本；正常启动与 JSON 导入都支持迁移，JSON 导出保留奖励记录。账号继续使用各自的玩家存档；重置存档同时重置剧情与签到进度。

实现入口：`src/ui/HubRewards.tsx`、`src/ui/hubRewards.css`；奖励曲线与领取计划集中于 `src/domain/progression/rewards.ts`，日序检查与账本归一化在 `rewardState.ts`。
