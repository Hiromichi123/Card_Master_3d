# 天梯赛（2026-10-11）

## 本轮开放范围

- 对战模式页「活动模式」下面新增天梯赛，与活动大厅天梯项进入同一页面。
- 三个主按钮：单人匹配、2v2（NEW）、配置卡组。前两项禁用并标注暂未开放；未接联机、匹配、AI替代对手、赛季奖励或实际积分结算。
- 左侧显示专用天梯卡组12槽缩略图及强度；中央为原创低面旋转水晶，下面显示积分/称号；右侧为0–2400纵向段位阶梯。
- 水晶按段位换色，设置「减弱动态」后停止旋转/浮动；WebGL不可用时仅水晶改静态占位，DOM配置和导航继续可用。

## 强度计算

- 卡牌权重 = `7 - rarities.json.level`，D=1、SSS=7，半档保持0.5步长。活动卡采用自己的level：`#elna`为7，`#yoroi`为4，不使用图鉴排序序号。
- 出战牌逐张求平均，重复卡照算，空槽不算0；内部保留精度，显示两位小数。
- 在相邻普通稀有度的权威配色之间插值，显示渐变边框和色带。空组显示「未配置」，未知卡/稀有度显示「无法评估」，缺库存等继续沿用卡组规则提示。
- 指标仅供未来近似强度匹配使用，不声称等价于卡牌实际胜率；当前没有匹配队列。

## 四套配置与兼容

- 配置页四个固定页签：卡组1、卡组2、卡组3、天梯赛卡组。
- 切页签仅切编辑对象；普通卡组通过「设为普通出战」显式选择。天梯卡组不会被设为普通出战，战役/迷宫继续读取普通active。
- 从天梯「配置卡组」进入默认选天梯页签；页面内可前往对战模式或返回天梯。普通配置入口不继承上一次的天梯编辑上下文。
- schema升级至4：`normalDeckIds`保存三普通槽映射，`ladder`保存积分和专用deckId，内容仍在`decks`。初始天梯复制已有active配置，之后独立；不增减库存。普通2/3不足时补空槽。
- 旧档保留所有原卡组和有效active、迷宫与奖励账本；超出三槽的旧卡组可通过「其他已有卡组」访问。新增ID避免碰撞；迁移不重复生成卡组。
- 多卡组修改按ID保存，失败草稿保留于会话。页内导航/普通出战切换等待明确保存结果，失败留在原页并可重试；全局导航后重新进配置可找回失败草稿。天梯预览读取最近已保存版本，未保存时有提示。

- 收藏拥有率＝完整卡库里已拥有的不同卡ID数÷完整卡库不同卡ID总数，含完整活动卡；重复库存只算1种，未知/不完整ID不计，空池0%。配置页和榜单共享`collectionCompletion`，不受当前筛选/卡组影响；领奖获得新品种会更新。

1. 对战模式页的天梯在活动模式正下方，两个天梯入口进入相同页面。

4. 天梯→配置默认天梯页签；修改后返回天梯缩略图和强度同步，普通出战卡组不变。
5. 连续切换1/2/3/天梯编辑，再离开和重载，各套各自保留；普通出战需显式设置。
6. 配置页能去对战模式和回天梯；旧档额外卡组仍可找到。
7. 更高积分存档的称号、水晶颜色、阶梯高亮一致；世界档2400以上正文不被截断。
8. 新一轮：玩家/卡组贴左边，左下排行榜不覆盖卡组；九档logo各不相同且均有色彩，奖励行完整，三主按钮一行、胜负在上方，透晶内可见金球。
