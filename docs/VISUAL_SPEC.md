# 视觉规范与参考效果清单

日期：2026-10-05。
**3D 战桌 + 实体卡牌 + 立体技能特效 + DOM 信息界面**。
---

## 0. 总体原则

1. **可读性优先于华丽度**。中文名称、ATK/HP/CD 数值、技能说明在 1280×720 下必须能直接读清。
   任何遮挡数值的特效按缺陷处理，不按风格问题处理。
2. **卡牌是实体，不是贴图**。必须有厚度、边缘、阴影、透视；禁止用「CSS 倾斜的平面 UI」代替。
3. **特效有物理过程**。火球要有飞行轨迹与命中，闪电要有空间电弧，护盾要有明确反馈；
   不允许「播放一张图标」充数。
4. **复用优先**。同类技能共享发射器、材质、粒子图集，参数只调强度/数量/尺度，
5. **不做的事**：不做完整角色建模、骨骼动画、自由漫游场景。

## 4. 技能特效模板

每个技能使用「**起手 → 发射/施法 → 命中 → 余波**」四段结构。
数值与演出内容分别定义：数值在规则层，演出在表现层（PLAN 第 4.1 节）。

`n` 参数主要调整**强度、数量、尺度**，不是复制新效果。

| 模板 | 玩法 | 必须可观察的要素 | 编号 |
| --- | --- | --- | --- |
| 普通攻击 | 对位普攻 / 本体受击 | 卡牌蓄力前移、挥击弧、接触闪光、伤害数值、轻微镜头反馈 | `V-FX-ATK` |
| 火焰/爆破 | 火球、群体火球、炮击、群体爆破、爆裂 | 弧线弹体、火星拖尾、冲击环、烟尘与碎屑 | `V-FX-FIRE` |
| 冰 | 冰封、群体冰封 | 冰晶弹体、命中结晶、地面霜环 | `V-FX-ICE` |
| 电 | 闪电、群体闪电 | 三维折线/带状电弧、短暂照明、闪击光点 | `V-FX-BOLT` |
| 防御/闪避 | 防御、破甲、免疫、闪避 | 曲面护盾、裂纹/碎片、技能伤害挡下提示、侧闪残影 | `V-FX-GUARD` |
| 增益/治疗 | 祝福、群体祝福、振奋、群体振奋、治愈、群体治愈、恢复 | 上升粒子、法阵、剑形/治疗符号、ATK/HP 变更反馈 | `V-FX-BUFF` |
| 负面/生命交换 | 诅咒、受伤、吸血、狂暴、自毁 | 紫色束缚、红色流光、生命转移与消散 | `V-FX-DEBUFF` |
| 卡牌流转/复制 | 抽卡、还魂、加速、延迟、分身、复制、不死、复活 | 卡背飞行、时钟环、分裂残影、返回手牌/准备区 | `V-FX-FLOW` |
| 被动信息 | 沉默、飞行 | 静态状态图标 / 轻量悬浮提示，**不持续占用重粒子** | `V-FX-STATUS` |

### 硬性要求

| 编号 | 规范 |
| --- | --- |
| `V-FX-1` | 命中瞬间与数值变化必须同时可见；数值不能先于特效或晚于特效一个节拍。 |
| `V-FX-2` | 群体技能的重叠效果**不得遮住核心数值**（HP/ATK 变化要能读出来）。 |
| `V-FX-3` | 对象离场前保留视觉代理，避免目标先消失导致弹体追向空位置。 |
| `V-FX-4` | 低/中/高画质档都必须有可读版本；低档可减粒子与后处理，**不能减掉命中反馈本身**。 |
| `V-FX-5` | 演出设置（正常/快速/跳过、镜头震动、低特效）**不得改变战斗结果**。 |
| `V-FX-6` | 粒子用 Points 或批量 billboard/instancing，固定缓冲区与对象池；不为每颗粒子建 React 组件。 |
| `V-FX-7` | 冰封原实现只造成伤害，**不新增**冻结/跳过回合机制（PLAN 第 4.2 节）。 |
| `V-FX-8` | 飞行不擅自加入未实现的「对空」技能（`对空` 属未识别 trait，见 `docs/SKILL_COVERAGE.md`）。 |

## 未来盘面（2026-10-09）

设置与战斗设置中的“台面”新增 `未来`。

- 以白色陶瓷装甲为主，灰银机械框架为辅，青蓝能源作为小面积强调。双方战斗区、等待区使用四块大装甲功能板，牌堆另有小型承托位。
- 盘内：功能板上的低亮扫描光带、中央能源脊、两侧缓慢旋转与轻浮动的棱晶反应核心。卡牌和槽位的世界坐标不变，装甲顶面留在卡牌下方。
- 盘外：两条侧轨上的悬浮探针来回巡航，带旋转环与窄扫描束；机械端柱、散布于边缘的上升能源微粒与浅色机库地面形成空间层次。
- 同类装甲细节、支撑、散热槽和能源条按材质实例化批量绘制。低画质减少微粒与环段，静止设置冻结动效但保留模型；模型不参与交互射线或战斗随机流。
- 白色板面不发光，泛光阈值单独提高，发光只集中在能源装置。灯光方向保留，主光与轮廓光在该主题中使用偏冷配色。

实现入口：`src/rendering/battle/MechaTable.tsx`；主题数据：`src/rendering/table/themes.ts`。不需要外部贴图、模型下载或新增依赖。本次未运行实例、测试、构建或截图检查。

双方牌堆外侧增加水平浮空的矢量数字 `n/m`，字面宽于牌堆，`n` 为绿色，`/m` 为黄色；双方弃牌堆只显示红色数量。使用自建方形棱角数字，不依赖远程字体或图片。`n` 随显示层事件更新，`m` 为本局初始配置牌组张数，冷却奖励牌和召唤单位不增加分母。
仅该台面显示这些数字，装饰模型不参与交互射线或战斗随机数。科技立方体的同类结构按材质实例化，远景不投射阴影。
实现位于 `MechaVoid.tsx`、`MechaPileCounter.tsx`；仅源码编辑，未运行实例、测试、构建或截图检查。

## 火山：六角玄武岩柱与熔岩战台（2026-10-10）

火山主题使用独立的六边形岩台，取消交替棋盘格及原圆桌地面。原火山边框的金属材质保留，轮廓改为带厚度和倒角的六边形；深灰粗糙岩台的中央开放曲折熔岩河道，支流沿战斗列间隙延伸。熔岩使用程序化流动纹理和高亮发光，配合橙红局部灯光、内缘细熔岩线和主题泛光。低画质仍显示流动岩浆与局部灯光。

岩台落在中央巨大六边形玄武岩柱顶端，周围以台面为圆心、约 32 世界单位范围内铺设高低起伏的六边形岩柱，色彩在灰黑之间变化。石质法线和粗糙度由现有材质生成器提供；柱群实例化渲染，画质控制密度。中央承托柱延伸至下方连续实心基岩地层，柱缝下有较暗熔岩，避免低视角露出空洞。碎石使用同类灰黑色材质，并避开战斗槽、等待槽、牌堆与熔岩支流，不遮挡卡牌。既有火焰余烬上升和热气效果保留并扩大覆盖；减少动态设置冻结环境动效。

## 全局数字字体（2026-10-10）

所有运行时数字统一为战役章节编号使用的 Georgia。DOM 使用 `Game Numerals` 本地字体别名，`unicode-range` 仅包含 0–9，分别声明正常、粗体、斜体与粗斜体；将别名置于现有文字字体栈之前。因此货币、概率、计数、关卡编号、表单及版本号共用数字字体，中文与字母仍使用原字体。
