# 视觉规范与参考效果清单

日期：2026-10-05。对应施工清单 P0-1，并按用户已确认的方向：
**3D 战桌 + 实体卡牌 + 立体技能特效 + DOM 信息界面**。

本文件是可执行的验收依据。P1 的验收条目直接引用这里的编号（如 `V-CARD-2`）。
凡是「必须可观察」的条目，都要能在 P1 的截图或短视频里被指认出来，不能只写在文档里。

---

## 0. 总体原则

1. **可读性优先于华丽度**。中文名称、ATK/HP/CD 数值、技能说明在 1280×720 下必须能直接读清。
   任何遮挡数值的特效按缺陷处理，不按风格问题处理。
2. **卡牌是实体，不是贴图**。必须有厚度、边缘、阴影、透视；禁止用「CSS 倾斜的平面 UI」代替。
3. **特效有物理过程**。火球要有飞行轨迹与命中，闪电要有空间电弧，护盾要有明确反馈；
   不允许「播放一张图标」充数。
4. **复用优先**。同类技能共享发射器、材质、粒子图集，参数只调强度/数量/尺度，
   不复制整套效果（PLAN 第 3.2 节）。
5. **不做的事**：不做完整角色建模、骨骼动画、自由漫游场景（PLAN 第 1 节列为后续扩展）。

## 3. 战桌与场景

| 编号 | 规范 |
| --- | --- |
| `V-TABLE-1` | 桌面材质有可见细节（石材/木纹级别），不是纯色平面；不接受镜面全反射导致卡面读不清。 |
| `V-TABLE-2` | 槽位边界用低对比的环/框表现，可放置状态才提高对比，避免常态干扰卡面。 |
| `V-TABLE-3` | 光照：一盏主光 + 环境光即可起步；主光方向固定，避免卡面在动画中忽明忽暗。 |
| `V-TABLE-4` | 环境反射用 HDRI 时按质量档降分辨率；低档可退化为纯光照无反射。 |

### 3.1 台面主题

`V-TABLE-5` 战斗台面是**可切换的主题**，不是写死的一种外观。一套主题同时决定：
格子垫的浅/深两格、边框、嵌线色、桌面大板、背景、雾、槽位强调色、以及泛光的性格。
只换材质不换环境会造成「桌子换了、空气没换」的割裂感。

`V-TABLE-6` 材质一律写成**纯数据**（`SurfaceSpec`），由构造器生成材质。
新增一套台面只加一条数据，不改场景代码，也不需要为它准备贴图。

`V-TABLE-7` 贴图**程序化生成**（木纹/大理石/石面/拉丝金属），不引入二进制素材：
一个主题换配色不必再出一套图，且任何视口下都清晰。
生成必须**确定性**（固定种子），否则截图对比与视觉回归不可复现。

`V-TABLE-8` 格子垫用**实例化**渲染。8×8 的独立 mesh 会把 draw calls 从 178 推到 244，
越过 `V-PERF` 的上限；按深浅分成两个 InstancedMesh 后是 2 次。

`V-TABLE-9` 主题自带的泛光阈值只在与本项目画面构成相符时才可采用。
棋盘那类「深色场景 + 小体积高亮」可以低到 0.62；本项目卡面是大块高亮表面，
阈值过低会让整张卡发光、糊掉插画与中文。阈值取「主题值与下限 0.9 的较大者」。

`V-TABLE-10` 场景必须有**运行时生成的环境贴图**（`RoomEnvironment` + `PMREMGenerator`），
不下载 HDR 文件。台面用的是 `MeshPhysicalMaterial`，它的 `clearcoat`、`transmission`、
`envMapIntensity` 只有在有环境贴图时才起作用——没有它，上漆的木头、大理石与石材
会长得一样平。

`V-TABLE-11` 灯光固定为**三盏 + 一点环境光**：一盏投影主光、一盏冷色补光（把暗部托起来）、
一盏低位轮廓光（把主体从背景里分出来）。主题只调环境光强度、背景与雾——
换主题换的是场地氛围，不是重新打一次光。

`V-TABLE-12` 部分台面带**天气**（草地会摇、荒原浮尘、火山余烬、雪原落雪）。
天气只影响表现，不参与任何规则；只用 `Points` 与一个 `InstancedMesh` 两个图元实现，
整层只占几次 draw call；低画质档减少数量，「减少动态」时**冻结而不是移除**。

台面清单见 `src/rendering/table/themes.ts`，天气见 `src/rendering/table/weather.tsx`；
来源与许可见 `assets-sources.json` 的 `portedCode` 段。

## 4. 技能特效模板

每个技能使用「**起手 → 发射/施法 → 命中 → 余波**」四段结构。
数值与演出内容分别定义：数值在规则层，演出在表现层（PLAN 第 4.1 节）。

`n` 参数主要调整**强度、数量、尺度**，不是复制新效果。

| 模板 | 玩法 | 必须可观察的要素 | 编号 |
| --- | --- | --- | --- |
| 普通攻击 | 对位普攻 / 本体受击 | 卡牌蓄力前移、挥击弧、接触闪光、伤害数值、轻微镜头反馈 | `V-FX-ATK` |
| 火焰/爆破 | 火球、群体火球、炮击、群体爆破、爆裂 | 弧线弹体、火星拖尾、冲击环、烟尘与碎屑 | `V-FX-FIRE` |
| 冰 | 冰封、群体冰封 | 冰晶弹体、命中结晶、地面霜环 | `V-FX-ICE` |
| 电 | 闪电、群体闪电 | 三维折线/带状电弧、短暂照明、闪击光点 | `V-FX-BOLT` |
| 防御/闪避 | 防御、破甲、免疫、闪避 | 曲面护盾、裂纹/碎片、技能伤害挡下提示、侧闪残影 | `V-FX-GUARD` |
| 增益/治疗 | 祝福、群体祝福、振奋、群体振奋、治愈、群体治愈、恢复 | 上升粒子、法阵、剑形/治疗符号、ATK/HP 变更反馈 | `V-FX-BUFF` |
| 负面/生命交换 | 诅咒、受伤、吸血、狂暴、自毁 | 紫色束缚、红色流光、生命转移与消散 | `V-FX-DEBUFF` |
| 卡牌流转/复制 | 抽卡、还魂、加速、延迟、分身、复制、不死、复活 | 卡背飞行、时钟环、分裂残影、返回手牌/准备区 | `V-FX-FLOW` |
| 被动信息 | 沉默、飞行 | 静态状态图标 / 轻量悬浮提示，**不持续占用重粒子** | `V-FX-STATUS` |

### 硬性要求

| 编号 | 规范 |
| --- | --- |
| `V-FX-1` | 命中瞬间与数值变化必须同时可见；数值不能先于特效或晚于特效一个节拍。 |
| `V-FX-2` | 群体技能的重叠效果**不得遮住核心数值**（HP/ATK 变化要能读出来）。 |
| `V-FX-3` | 对象离场前保留视觉代理，避免目标先消失导致弹体追向空位置。 |
| `V-FX-4` | 低/中/高画质档都必须有可读版本；低档可减粒子与后处理，**不能减掉命中反馈本身**。 |
| `V-FX-5` | 演出设置（正常/快速/跳过、镜头震动、低特效）**不得改变战斗结果**。 |
| `V-FX-6` | 粒子用 Points 或批量 billboard/instancing，固定缓冲区与对象池；不为每颗粒子建 React 组件。 |
| `V-FX-7` | 冰封原实现只造成伤害，**不新增**冻结/跳过回合机制（PLAN 第 4.2 节）。 |
| `V-FX-8` | 飞行不擅自加入未实现的「对空」技能（`对空` 属未识别 trait，见 `docs/SKILL_COVERAGE.md`）。 |

## 10. P1 需要补齐的实测记录

写入 `docs/validation/P1.md`：参考机器 CPU/GPU/浏览器/分辨率/DPR、冷加载耗时、
首次 Shader 编译卡顿、预热后帧耗时、纹理 MiB、draw calls、活跃粒子数。
若视觉质量或可读性不达标，**先调整镜头/材质/VFX，再进入外围玩法**（CHECKLIST P1 验收）。
