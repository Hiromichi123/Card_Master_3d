## 2. 与旧版的对应关系

顺序基线（`docs/rules.md` 第 2 节）逐条实现，每一步都在 `endTurn` 里有对应位置：

```
胜负预检 → 双方 CD 递减 → 部署 → 上场技能
→ 当前方从左到右攻击 → 死亡与死亡技能 → 槽位整理 → 胜负 → 换边 → 新回合抽牌
```

几处**刻意保留**的旧版行为：

- **CD 是双方一起递减的**，不是只在当前方回合（旧版 `BBS:1517`）。
  测试里用「一次 endTurn 看双方」而不是两次分别跑，才验证得了这一点。
- **同回合部署的卡会立刻攻击**。这一点最初被测试误判成「伤害翻倍」，
  查清后按旧版行为保留。
- **免疫只挡技能伤害，普通攻击绕过**（`docs/rules.md` 第 4.5 节）。
- **地对空不能伤害飞行卡**，改为把攻击者的原始攻击力打到飞行卡所属方的本体上。
- **冰封只造成伤害**，不新增冻结或跳过回合的机制。

几处按 PLAN 允许的差异（编号对应 `docs/rules.md` 第 10 节）：

| 编号 | 差异 | 实现位置 |
| --- | --- | --- |
| D1 | 伤害不再由动画回调交付 | 整个引擎；`Resolution` 一次算完 |
| D2 | 胜负检查计入牌堆 | `hasCards()` |
| D3 | 新增回合上限平局 | `endTurn` 第 8 步 |
| D4 | 同时死亡改为对称判定（双方都出局即平局） | `checkOutcome()` |
| D6 | 归属不做静默兜底 | `SkillContext.owner` 是必填字段 |
| D9 | CD 建模在卡实例上 | `CardInstance.cd` |
| D10 | 已死亡单位不再发起行动 | `resolveAttack` 开头与攻击循环双重检查 |
| D11 | 死亡分组用 `stateGroupId`，不用 `id()` | `removeDead()` |
| D14/D15 | 独立带 seed 的 RNG | `rng.ts` |

## 3. `docs/rules.md` 第 12 节的 7 个待复核项

| # | 问题 | 结论 | 依据 |
| --- | --- | --- | --- |
| 1 | 飞行重定向是否应绕过免疫与防御 | **保持绕过**，与旧版一致 | 旧版该路径直接扣本体生命、不经 `deal_damage_to_slot`（`BBS:1347-1368`）。改成走防御会变成**行为变更**，不在本轮范围内 |
| 2 | 同时死亡的判定时机 | **在两个明确节点判定**：`endTurn` 开头与全部攻击+死亡处理之后 | 不再依赖「下一个 cleaning 阶段」这种时序巧合 |
| 3 | 复活体本轮能否攻击 | **不能**。复活把卡放回准备区并重新套用卡牌原始 CD | 与旧版 `CMP:49-50` 一致；需要空准备槽，没有则留在弃牌堆 |
| 4 | 自毁与死亡处理是否会重复处理同一张卡 | **不会**。自毁只把 HP 置零；真正的移出与死亡技能统一由 `removeDead` 处理，且有 `deathHandled` 标记 | 与旧版「自毁自己走一套流程」不同，这是 D10/D11 的一部分 |
| 5 | 弃牌堆取牌是否有阻塞动画重入 | **不适用**。引擎里没有任何阻塞或动画回调 | 还魂直接改区域数据 |
| 6 | 「复制」每回合限制与回合数的对应 | **按回合重置**：`copyUsedThisTurn` 在换边时清零 | 与旧版 `copy_usage_state` + `_advance_owner_turn` 的意图一致，但用的是 `turnNumber` 语义，不另立第三套回合标记 |
| 7 | 分身共享状态组的行动限制 | **没有按组限制行动**：每个槽位各自攻击一次，共享的只是数值（HP/ATK） | 旧版分身共享 `CardData`，但攻击是按槽位遍历的（`BBS:602-615`）。因此模型里**删掉**了原先设想的 `actedThisTurn` 字段——它暗示了一条并不存在的规则 |

## 6. 已知局限（本轮范围之外）

1. **AI 只出一张牌然后结束回合**。它不是有策略的对手，目的是让 P3 先跑通一整局。
2. **没有实现能量/费用**。旧版没有这个系统，本轮也不新增。
3. **未覆盖的 10 个族**（`docs/SLICE.md` 第 4 节）在 P4 补齐；引擎的族表已经能容纳它们，
   缺的只是规则实现本身。
4. **演出层尚未接入**。`Resolution.patches` 已经有数据，但没有播放器；
   那是 P3 的「将演出层与规则 Resolution 连接」。
5. **没有跑过真实卡池的完整对局**。测试用的是构造出来的小卡组；
   用演示牌组（23 张切片）跑对局需要渲染层或一个命令行驱动，留到 P3。
