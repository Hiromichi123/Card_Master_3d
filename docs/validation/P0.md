### 校验机制本身也验证过

只跑一次 `--check` 通过不能说明它真的在检查。另外做过一次篡改测试：

```
篡改 src/data/stages.json（改一个章节名）
  → import --check 退出码 1   （检测到了）
  → 重新运行写入模式
  → import --check 退出码 0   （恢复了）
```

`.gitattributes` 固定了 `* text=auto eol=lf`。这不是风格问题：
`--check` 按文本比对生成物，如果 Git 在检出时把 LF 换成 CRLF，
新克隆的仓库跑 `--check` 会**必然失败**。

### 已修掉的两个可重复性缺陷

1. **报告自我引用**：导入报告原先在正文里列出「本次哪些文件有差异」，
   而报告自身也在那个列表里。于是写入模式与 `--check` 模式生成的报告内容不同，
   `--check` 永远失败。现在差异只打印到标准输出，报告正文不包含运行期状态。
2. **行尾漂移**：见上，用 `.gitattributes` 固定。
