# 人机 AI 与学习工具

本次完成规则 AI、难度/风格、Worker、权重优化与小模型模仿训练工具。**未启动游戏，未执行测试、类型检查、构建、评测、数据生成或训练**。下列命令留给后续手动执行；没有训练产物，也没有实测胜率或性能结论。

## 游戏内使用

在“战斗设置”中选择人机难度、风格和决策策略；设置随现有玩家存档保存，旧存档补默认值。

| 项目 | 行为 |
| --- | --- |
| 难度 | 简单、普通、困难、Boss：增加候选宽度、未知局面采样、后续行动分支与搜索步数；不增加卡牌数值、不开放隐藏信息 |
| 风格 | 均衡、进攻、防守、控制：调整本体血量、场上攻防、技能、等待区节奏等评分权重 |
| 旧版基础 | 短 CD 出牌、使用冷却牌、随机插队、部署成熟卡；保留为对照 |
| 规则推演 | 合法动作排序，采样未知局面，调用真实引擎完成有限深度的后续行动，再评分选择 |
| 学习＋推演 | linear 模型替换评分权重；mlp 模型辅助排序及搜索平分时的偏好；引擎结算与合法性约束保留。未导入模型时使用规则推演 |

深渊本战的普通/困难/噩梦分别覆盖为普通/困难/Boss，风格和策略仍采用玩家设置。其它已接入 `BattleScene` 的战役、演示、活动以及本地上方 AI 共用这套接口。风格与搜索预算是设计档位，难度强弱是否单调仍需实测。

打开“性能”读数后，战斗辅助栏会出现 AI 决策详情，可导出最近 50 次动作、候选评分、采样数、推演步数与回退原因。这不是完整对局回放，也不是训练数据；训练样本使用下方 `ai:generate`。

## 决策规则与边界

`ai/actions.ts` 枚举每张成熟卡的每个合法插入点（客场固定先部署，不再枚举先后手）、每张手牌的每个空等待槽、每个冷却牌目标及结束操作。相同冷却牌合并为一个等价来源。所有动作经 `validateCommand` 校验，不包含主动认输。客场窗口只允许部署与结束。

`ai/observation.ts` 只保留双方公开战斗/等待/弃牌、自身手牌和自身剩余牌组组成。自身牌堆组成排序后传入，真实顺序、实例 ID 和未来随机状态不传入。敌方未知手牌与牌堆仅有数量，通过**独立提供的公共卡牌库**及公开已见卡的等级估计采样；不读取真实敌方牌组。默认敌方手牌隐藏，同机本地选卡模式使用公开手牌观察。可见深渊培养卡保留当前数值，未见敌人不会泄漏其培养定义。

假设世界使用独立 seed 与 RNG，真实状态不被推演修改。候选之间采用相同采样，减少比较噪声。真实 `applyCommand` 处理上场技能、自毁、死亡连锁、飞行、先锋、免疫、反弹、持续状态等机制；AI 只评分，不另造一套扣血规则。普通/困难/Boss 都属于有限深度的采样搜索，不是完美信息 minimax。

| 难度 | 根候选上限 | 采样世界 | 每样本分支 | 交棒观察上限 | 单分支动作上限 | 引擎调用预算上限 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 简单 | 6 | 1 | 1 | 1 | 12 | 120 |
| 普通 | 10 | 2 | 1 | 2 | 22 | 640 |
| 困难 | 12 | 3 | 2 | 2 | 26 | 1900 |
| Boss | 16 | 3 | 2 | 2 | 32 | 3200 |

交棒观察上限是 `turnIndex` 的增长数，不把客场部署当作额外攻击回合。每候选获得相同动作预算，达到预算会提前停止；搜索内部的超长操作窗口最多进行 12 次动作后尝试结束。简单档在近分候选内有少量探索，普通档概率更低。实际开销取决于 trait 连锁，一次引擎调用也可能处理多个技能。

浏览器在独立 Worker 中推演，等待上限 2.5 秒；不可用、报错或超时时转入轻量规则评分。离开、开新局、切换托管、更新 AI 设置/模型会作废过期结果；动作仅在会话下一帧提交。模型不能跳过引擎合法性校验。回退时强度可能下降，不能把预算上限当作运行耗时保证。

## 无渲染工具与执行顺序

需要项目现有 Node/npm 依赖；Python 工具仅使用标准库，无须安装 PyTorch。命令在项目根目录执行。`run.mjs` 会在**手动执行命令时**用 Vite 打包领域引擎为 Node 工具，临时输出到忽略的 `.ai-cache`；不会启动网页或游戏实例。

1. 导出特征格式并评测初始规则 AI：

```powershell
npm run ai:schema -- --out artifacts/ai/schema.json
npm run ai:evaluate -- --games 32 --seed 800001 --difficulty normal --opponent baseline --out artifacts/ai/rules-vs-baseline.json
npm run ai:evaluate -- --games 32 --seed 900001 --difficulty hard --opponent heuristic --out artifacts/ai/hard-vs-normal.json
```

同一个 seed 的场景配对互换策略所在阵营，使开局顺序和牌组差异尽量均衡。报告胜/负/平、达到动作上限的截断局、平均动作数、主场行动数、搜索调用数与耗时。截断单独计数，在优化得分中不计为平局；默认每局最多 1600 次动作，可用 `--max-actions` 改。

2. 权重学习：

```powershell
npm run ai:tune -- --games 24 --generations 12 --population 6 --seed 100001 --opponent heuristic --out artifacts/ai/weights.json
npm run ai:evaluate -- --model artifacts/ai/weights.json --games 48 --seed 3000001 --difficulty normal --opponent heuristic --out artifacts/ai/weights-eval.json
```

演化式扰动从当前规则权重开始，保留当前候选，按固定训练 seed 对局选择权重，不更改引擎或牌组。默认调参用简单档节约开销，可指定难度；推演策略的档位也需要在报告里保持一致。默认留出评测使用 seed + 1,000,000 且不同牌组等级范围，训练过程不按留出结果选权重。旁边的 `.report.json` 保存训练历史、留出成绩和原权重对照。此工具目标是**可优化**，不保证优化后一定更强。

3. 教师数据与小模型：

```powershell
npm run ai:generate -- --games 120 --seed 400001 --difficulty hard --opponent heuristic --out artifacts/ai/teacher.jsonl
python scripts/ai/train_small.py --data artifacts/ai/teacher.jsonl --epochs 25 --hidden 32 --out artifacts/ai/small-model.json
npm run ai:evaluate -- --model artifacts/ai/small-model.json --games 48 --seed 6000001 --difficulty hard --opponent heuristic --out artifacts/ai/small-model-eval.json
```

教师样本包含公开观察提取的候选特征、选择标签、对局 seed/标识和策略版本，不含真实未知牌堆或 RNG。数值完全相同的候选在训练数据中合并，避免等价等待槽造成重复标签。训练脚本按整个对局 seed 划分训练/验证/测试，双方和同局动作不能跨集合；至少需要三个不同 seed。单隐层 ReLU 网络用候选 softmax 与交叉熵训练，按验证损失选择模型，测试集合只报告一次。模仿准确率不等于胜率，仍要另跑独立对局评测。

4. 在战斗设置中导入输出的 `weights.json` 或 `small-model.json`，选择“学习＋推演”。只有载入并校验成功才启用，失败保留旧模型并显示错误。模型使用独立本机存储，不写入玩家账号存档；可卸载。普通游戏使用无需 Python、服务端或远程大模型。

## 模型格式与扩展

22 个稳定特征由 `FEATURE_NAMES` 定义，包括双方血量差、场上共享 HP/独立攻击价值、技能价值、准备/手牌节奏、冷却牌储备、拥塞、对位与插队后变化、动作类型。HP 按共享状态组计一次，分身的每次攻击分别计入。特征没有逐个技能的完整编码，教师模仿和 MLP 都有表达能力限制，复杂相互作用仍由搜索处理。

`card-master-ai` v1 模型只允许 finite 数值、精确特征名/维度、linear 或单隐层 mlp（最多 128 单元），不执行导入文件中的代码。文件最大 500 KB。修改特征结构后旧模型需重新训练；游戏导入会拒绝不匹配的结构。

可选 `--suite path.json` 接入特定模式/固定牌组：文件是非空 `[{"config":{"seed":1,"playerDeck":["C_001"],"enemyDeck":["C_002"]},"definitions":{...}}]` 数组。`config` 遵循现有 `BattleConfig`，自定义培养卡需提供完整 `CardDefinition` 与召唤映射；基础公共牌库始终独立提供。工具按评测 seed 覆盖 config.seed。若给定 suite，训练/留出同用该 suite，只有 seed 隔离；真正牌组留出应另备独立 suite 文件。默认随机套牌/切片还不能代表深渊所有成长组合，应使用实际模式套牌补充评测。

`scripts/ai/bridge.py` 提供 Python `BattleEnv`；Node `serve` 持续响应 JSON-lines `reset/step/close`。每步返回动态数量的合法候选特征、commands、mask、阶段、公开血量、终局奖励（胜 +1、负 −1、其它 0）和截断标识。`step` 下标只对应**当前**候选，不是跨局固定动作编号。对方行动仍由 TS AI 完成；Python 不复制规则。

未来加入 PPO/自博弈时需要对不同候选数做 padding＋mask，另建价值网络和对手快照池，正确区分真实终局与截断，不把等待区/插队动作硬编码为固定数量。**本次没有实现或运行 PPO 优化器，没有接入远程大模型**；已交付的训练器是权重搜索和小模型模仿学习，环境接口为下一步准备。
