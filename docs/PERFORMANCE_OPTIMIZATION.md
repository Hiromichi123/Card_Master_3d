# 上线前性能优化（2026-10-22）

本轮优先减少重复工作、切页时的同步计算和资源峰值。未改战斗规则、卡牌分辨率、模型细节、特效数量及画质档的 DPR 上限。

## 已完成

| 部分 | 调整 | 保留的表现 |
| --- | --- | --- |
| 大厅、商城图标 | 移除永久逐帧 DOM 测量；只在布局、滚动、缩放和实际过渡期间重新对齐 | 悬停抬升、旋转、按钮点击及跟随位置 |
| 3D 页面生命周期 | 战斗、登录、抽卡、工坊、战役及装饰画布在标签页隐藏或移出可视区域时暂停；恢复保留动画时间 | 不卸载资源，不重新加载场景 |
| 深渊水晶、特性浏览、天梯水晶、深渊背景烟雾 | 缓慢装饰默认按 30 Hz 更新；深渊卡片、水晶交互时恢复 60 Hz | 分辨率、材质、光效、实际动画时长不变；战斗和抽卡演出不限至 30 Hz |
| 标准盘面五面房间镜子 | 视锥和背面排除；相机静止时反射按 20 Hz 错峰刷新，相机移动时即时刷新 | 原反射分辨率、Drei 表面着色、颜色和反射强度；大理石地面的反射仍沿用原实现 |
| 材质静态资源 | 将 73 张表面纹理按原算法离线生成无损 RGBA PNG，约 13.2 MiB | 原尺寸、像素、色彩空间和法线朝向；未知参数保留程序化生成回退 |
| 材质复用 | 缓存贴图源，每个材质使用独立 UV 变换；释放材质时释放自己的纹理引用 | 不同物体的纹理缩放不再互相修改；异步解码完成后全部在用副本正常刷新 |
| 卡面加载 | 并发上限 4；按 LRU 同时限制 320 张及约 128 MiB 解码纹理预算 | 在用卡面不回收、不降分辨率；128 MiB 为软预算，不代表全游戏显存上限 |
| 登录资源 | 同一显示帧内的多个图片完成通知合并为一次 React 更新 | 原登录演出及卡面样本不变 |
| 普通 UI | 金边/填充慢渐变降低重复重绘频率，移除按钮被伪元素遮住的父层动画；图片异步解码、商城图片延迟加载，屏幕外商品/卡格跳过内容绘制 | 金色风格、流动路径、布局、介绍框和交互不变 |

## 资源维护

- 生成器：`scripts/bake-surfaces.mjs`，运行 `npm run assets:bake-surfaces`。
- 输出：`public/assets/surfaces/*.png`，索引：`src/data/surfaceTextures.json`。
- 使用项目已有 Node 运行时和构建依赖，不需要浏览器、GPU、在线资源或额外图形软件。
- 修改主题材质参数后重新执行生成器，再运行 `npm run build`。生成器不自动删除旧 PNG；运行时仅使用索引中的文件。
- 文件位于 `public`，Vite 构建会自动复制进 `dist/assets/surfaces`，运行游戏时无需实时生成这些已烘焙纹理。

## 检查及限制

新增检查覆盖加载并发/失败恢复、引用计数与显存回收、加载途中销毁、PNG 完整性、异步纹理副本刷新、布局空闲停转、画布后台暂停及恢复时钟、父组件重渲染后仍保留节流。类型检查及生产构建结果见本次交付记录。

后续上线清理已解决历史回归失败：当前99个测试文件、727项测试全部通过，类型检查、生产构建与资源检查通过。旧失败清单保留在 `PERFORMANCE_TEST_RESULTS.md` 作为历史基线；当前结果见 [上线准备记录](RELEASE_READINESS.md)。

按此前约定，本轮没有启动游戏实例、浏览器或截图检查，也未在实际核显上做帧率测量。因此没有宣称 FPS 提升百分比；画面和硬件帧时间仍需实机确认。慢速装饰的 30 Hz 与背景镜面 20 Hz 是本轮明确的时间采样取舍，主场景及战斗动画维持原渲染频率。

复测时建议比较生产构建中的大厅空闲、图鉴滚动、商城横滚、抽卡切池、标准盘面对局和深渊局间切换，并分开观察首次进入与预热后表现。保持同一窗口大小、画质及 DPR，对比 GPU 占用、P95/峰值帧耗时和连续切页后的纹理数量；后台恢复不应产生动画时间重置。
