# 技能与 trait 覆盖核查

日期：2026-10-05。对应施工清单 P0-7「核查 35 技能族、飞行和 47 种注册表未识别 trait，
输出 implemented / scene-rule / unimplemented / ambiguous 分类」。

**证据强度**：对旧项目全部 `.py` 文件（排除 `__pycache__`、`build`、`dist`）逐个 grep
每个 trait 字符串，并读完整的 `skill_registry.py`、`skill_base.py`、`skill_effects.py`
与 `battle_base_scene.py` 相关段落。**没有运行旧游戏**。结论以源码为准，带 `file:line`。

机器可判定的部分（是否被注册表命中）由 `scripts/import-legacy-data.py` 复现；
需要读场景代码的人工判定登记在 `scripts/trait-overlay.json`。本文档解释这些结论。

分类口径：

| 分类 | 含义 |
| --- | --- |
| `implemented` | 被 `skill_registry.py` 的正则/精确规则命中，旧版有规则实现 |
| `scene-rule` | 在战斗场景里实现，不在注册表 |
| `alias` | 已注册族的命名变体（数值形式落空或同义异形词） |
| `flavor` | 说明性文字，无机制 |
| `unimplemented` | 确认没有实现 |
| `ambiguous` | 证据不足，需人工复核 |

## 2. 调度模型（P4 必须照此理解）

| 触发点 | 是否派发 | 调用点 |
| --- | --- | --- |
| `ON_DAMAGED` | 是 | `battle_base_scene.py:1389` |
| `AFTER_DAMAGED` | 是 | `:1430`（仅 `actual_damage > 0`） |
| `AFTER_ATTACK` | 是 | `:1463` |
| `BEFORE_ATTACK` | 是 | `:1485` |
| `ON_DEATH` | 是 | `:1870` |
| `ON_DEPLOY` | 是 | `:1958` |
| `ON_ATTACK` | **否** | 只声明于 `skill_base.py:7` |
| `TURN_START` | **否** | 只声明于 `skill_base.py:14` |
| `TURN_END` | **否** | 只声明于 `skill_base.py:15` |

`BEFORE_ATTACK` 的效果**不内联执行**：场景先调 `get_animation()`，
把 `anim.on_hit = effect.execute` 挂上（`:1484-1501`），所以执行被动画命中帧门控；
效果不返回动画时才立即执行（`:1499-1501`）。每个技能每个触发点**只保留第一个**
产生动画的效果（`:1498` 的 `break`）。其余触发点内联执行。

`TargetType`（`skill_base.py:18-26`）已被导出（`__init__.py:4,28`）但**没有任何效果使用**。
`SkillRegistry.register_skill` / `trait_to_skill`（`skill_registry.py:59-65`）是死代码，
从未被调用——注册表实际是硬编码的 if/regex 阶梯，且**正则没有结尾锚点**
（`火球(\d+)` 能匹配 `火球1x`）。

新版把这套「动画命中帧决定技能伤害」的结构换成
`Command → Resolution(events + patches)`，`BEFORE_ATTACK` 在事件序列里有固定位置。

## 3. 35 个技能族

参数形式写作 `族n`，`n` 由 `re.match(r"字(\d+)", trait)` 取出。
「纯度」列区分该族的规则是否可以在不依赖渲染的情况下执行——
P2 需要 **pure logic** 的族能独立测试，**scene-dependent** 的族需要引擎提供对应抽象。

## 4. 47 种注册表未识别 trait 的分类

**穷尽 grep 的硬事实**：这 47 个字符串**没有任何一个出现在任何 `.py` 文件里**，
唯一的例外是 `对空`，它只出现在一句注释中（`battle_base_scene.py:1348`
「地面单位无法对空：伤害转移到防御者玩家」）。它们只作为数据存在于
`assets/outputs/*/cards.json`。

**因此 `scene-rule` 分类的数量是 0**：按「在注册表之外实现」的定义，47 个里没有一个符合。
全项目唯一的 trait 字符串场景规则是飞行规则，而它读的 `飞行` **不在**这 47 个里。

### alias（4）——命名变体

| trait | 对应族 | 证据 | 置信度 |
| --- | --- | --- | --- |
| `爆裂1` | 爆裂 | `skill_registry.py:268` 用**精确匹配**注册 `爆裂`，没有 `爆裂(\d+)` 正则；`skill_effects.py:1013-1046` 机制与词干一致 | 高 |
| `狂暴1` | 狂暴 | `skill_registry.py:244` 用 `trait == "狂暴"` 精确匹配；`skill_effects.py:769-815` | 高 |
| `延时1` | 延迟n | `skill_registry.py:134` 注册 `延迟(\d+)`；`skill_effects.py:1259-1290` 为敌方最左占用准备槽 CD+n。延时/延迟是同义异形词 | 中 |
| `治疗1` | 治愈n | `skill_registry.py:202` 注册 `治愈(\d+)`；`skill_effects.py:414-498`。治疗/治愈同义 | 中 |

前两个是**纯解析缺口**（数值形式落空），后两个是**同义异形词**。
本轮**不为它们自动建立别名规则**（PLAN 第 4.3 节：「不能未经核查自动当作同一规则」），
只在图鉴里标注为待确认。

| trait | 为什么不当作别名 |
| --- | --- |
| `对空` / `群体禁飞` | 概念上是飞行规则的反制，但 `battle_base_scene.py:1344-1345` 只检查 `飞行`；带 `对空` 但不带 `飞行` 的卡**没有任何收益**。PLAN 第 4.3 节明确要求不擅自加入未实现对空技能 |
| `闪避赋予3` | 「赋予」意味着把闪避给**别的单位**，与 `闪避n` 的自身闪避是不同的机制 |

| `流血2` / `燃烧2` | `受伤n` 是攻击后自伤，不是持续伤害；游戏里不存在持续伤害状态 |
| `圣盾1` | 与 `防御n` 同域但词干不同；**2026-10-07 由本项目补上**（旧注册表没有这一族），见 `rules.md` 第 13 节 |

### 判断成分说明

**没有任何设计文档、术语表或代码信号**能区分这些字符串是「未实现的机制」还是「设定文字」
（`README.md`、`docs/*` 里没有相关说明；`ui/tooltip.py:126` 只把 trait 原样渲染）。
所以 flavor / unimplemented 的划分对每一项都是判断，唯一可验证的硬事实是
「没有代码读取这个字符串」。`不屈`/`傀儡`/`决斗` 是判断成分最高的三项
（最可能其实是机制）；`魅惑`/`洞察`/`吞噬`/`传送`/`即时`/`先攻`/`先锋` 也可能被论证为 flavor。
若后续需要区分「缺失功能」与「装饰文字」，需要用户提供原始设计意图。

## 5. 对 P4 的含义

1. **P4 要覆盖 35 族 + 飞行**，但其中 4 族（沉默/免疫/不死/复活）的规则在场景层，
   实现时要放在引擎的位置相关规则里（沉默看对位、免疫只挡技能、不死回手牌、复活回准备区）。
2. **只有 `群体祝福n` 没有被任何卡牌引用**。P4 仍要覆盖它，
   但验收样例需要**人工构造**而不是从卡池里挑。
3. `冰封n`、`闪电n` 与 `火球n` 的规则**完全相同**，只在表现上不同。
   P4 的「不得为同类技能另建重复框架」正是针对这一点。
4. **47 个未识别 trait 在正式对局中不生效**，原描述保留在图鉴里，
   详情页显示为未实现，不自动创造新规则（PLAN 第 4.3 节）。
5. `反击n`、`抽卡n`、`还魂n`、`加速n`、`延迟n`、`自毁`、`分身`、`复制`、`爆裂`、`沉默`、
