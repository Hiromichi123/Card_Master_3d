# 切片牌、演示牌组与固定 seed 约定

日期：2026-10-05。对应施工清单 P0-12「选取约 16–24 张有代表性的切片牌，
准备至少两套有效牌组和固定 seed 战斗样例」。

**切片清单本身不写在这里。**牌表、数值、挑选理由、牌组构成与场景覆盖
由 `scripts/import-legacy-data.py` 生成在
[`docs/import-report.md`](import-report.md) 的「6.5 切片与演示牌组」一节，
随数据源一起更新，避免手抄数值产生漂移。

本文件说明**怎么用**这套切片。

## 1. 数据来源

| 文件 | 作用 |
| --- | --- |
| `scripts/slice-definition.json` | 人工挑选的意图：选哪些卡、为什么、牌组怎么配、要验哪些场景 |
| `src/data/slice.json` | 导入脚本校验后导出的结果，含真实 ATK/HP/CD/traits |
| `docs/import-report.md` | 可读的切片表与覆盖情况 |

导入脚本会校验这些不变量，任一条不成立就报错：

- 每张切片卡都存在，且 `status` 是 `complete`（未完成卡不能进战斗）；
- 每套牌组 ≤ 12 张、无重复 ID、引用的卡都在切片内；
- 每个场景声明的族**确实出现在切片里**（`covers` 用族 slug，`flying` 走场景规则校验）。

## 2. 固定 seed 约定

`slice-definition.json` 的 `seedBase` 是 `20261005`。派生方式：

| 用途 | seed | 说明 |
| --- | --- | --- |
| 演示战斗（玩家 vs 敌方演示牌组） | `seedBase` | P3 的默认对局 |
| 规则单测第 k 个用例 | `seedBase + k` | 每个用例固定，便于复现失败 |
| 仅调整演出速度的对照组 | 与对应基准**同一个 seed** | 正常/快速/跳过必须得到相同结果 |

**规则随机与表现随机必须分开**（PLAN 第 4.2 节）：
战斗使用 `BattleState.rng`，粒子/抖动使用另一条独立随机源。
画质档、粒子数量、帧率都**不得**改变 `BattleState.rng` 的消耗序列。

验收方式：同 seed、同 `Command` 序列，在普通/快速/跳过三种模式下
比较 `Resolution.events` 与 `finalState`，必须逐字节一致。

## 3. 场景与阶段对应

`src/data/slice.json` 的 `scenarios` 把「要验什么」和「用哪些族」绑在一起：

| 场景 | 首次需要通过的阶段 |
| --- | --- |
| S1 元素单体、S2 群体目标、S3 防御叠加、S4 飞行 | P3（代表玩法） |
| S5 沉默、S9 增益治疗、S10 抽卡与自毁 | P3–P4 |
| S6 死亡与复活、S7 分身与复制、S8 CD | P2（纯规则引擎，无渲染） |

P2 要在 `docs/validation/P2.md` 里逐条给出结论；其中
`docs/rules.md` 第 12 节的 7 个待复核项必须全部有答案。

## 4. 切片没有覆盖的部分

切片覆盖 25 个族 + 飞行规则；**未覆盖的 10 个族**是：
狂暴、炮击n、诅咒n、群体祝福n、群体爆破n、群体治愈n、免疫、受伤n、还魂n、吸血n。

其中 `群体祝福n` **没有任何卡牌引用**（见导入报告第 1 节），P4 需要人工构造验收样例。
其余 9 个有卡可用，P4 覆盖时从卡池挑即可，不需要进入本切片。

`爆炸/爆裂` 虽然不在未覆盖清单里，但切片里只有 `SS+_011`（爆裂1）覆盖死亡触发；
P4 还要覆盖 `炮击n`、`群体爆破n` 与 `爆裂` 的规则差异。

## 5. 与图上素材的关系

`scripts/prepare-assets.py` 默认只派生**切片 23 张**的卡面三档，
加上卡背、图标、技能图、海报与背景。完整 247 张在 P5/P7 用 `--all` 生成。
切片的三档实测体积见 `docs/validation/P0.md`。
